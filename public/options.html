Lamport Warden

Warden is on.

From now on it reads each request a site makes of your Solana wallet, before the wallet is asked. Most of the time you will see nothing. When a request is new, it says what it does in one sentence. When it is how wallets get emptied, it stops it.

Pages that were already open need to be loaded again before Warden is in front of them.

See it work with a practice wallet

That opens a page on warden.lamportrobotics.com. Nothing leaves this browser until you press it.

To see what Warden does without risking anything:

Reading lookup tables

Most swaps name their accounts by position in a table stored on chain. To say where the money goes, Warden has to read that table from a Solana RPC. Unless you turn on simulation or Sentinel reporting below, this is the only network call it makes. The RPC learns which table was asked for and your IP address. It does not learn your wallet address, the transaction or the site.

Simulating transactions

Warden reads payments and token transfers exactly. A call to any other program, a swap for example, it can only name. With simulation on, Warden sends such a transaction, unsigned, to the RPC chosen above and asks what it would do, so it can tell you what would leave your wallet and what would arrive. The RPC sees the transaction, and the transaction names your wallet. That is why this is off until you turn it on.

A decoy first (an experiment)

Connecting a wallet to a site hands the site an address and nothing else. With this on, a site Warden has not seen before is handed a decoy's address first: one that holds something and that nobody here has a key to, so nothing it is asked to sign can be signed. A site that asks the decoy to give everything away is a thief, caught before it has seen your address. A site that does not is then connected to your own wallet, and asks again. It costs one more press the first time you use a site, and it only works with wallets that connect the newer way.

The decoy has to be an address that really holds something, or a thief that looks it up will see an empty wallet and leave it alone. Warden asks your RPC what it holds; the RPC learns the decoy's address, not yours. Never use an address you have the key to.

So that a site you already use is not shown a decoy again, Warden keeps a mark for each site that passed, up to five hundred, in this browser and nowhere else. It is the one record Warden keeps of sites you used. Turning this off removes it.

Sites allowed to ask for your Privacy Rings keys

A Privacy Rings wallet derives its keys from one signature. Whoever gets that signature can read your private balance and history for good. Warden blocks the request from every site that is not on this list, and asks you to confirm it on the ones that are.

    Wallet doors Warden cannot guard

    A wallet put these objects on a page in a way nothing can be placed in front of. A page that calls one of them directly reaches the wallet without Warden. The same wallet's Wallet Standard connection, which most dapps use, is guarded.

      Sentinel

      Sentinel is Warden's watching service. It runs on a Lamport server, watches the wallets you give it after you sign, and tells you in one sentence when something looks wrong. You set it up on the Sentinel page, not here:

        Sentinel sees only the chain, so it cannot tell a payment you made from one a thief made with your key. With this on, when a wallet you linked on the Sentinel page signs a transaction you let through, Warden sends Sentinel that wallet's address and the transaction's signature. Both are public on the chain once the transaction lands. Nothing else is sent: not the site, not the transaction, not your history. With this off, Warden sends Lamport nothing at all.

        What Warden remembers

        For each wallet address, the addresses it has paid and how often. It learns one only when a request you let through comes back signed. It is kept in this browser and sent nowhere.
